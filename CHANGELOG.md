- 2026-11-23: the chat says so when a session has no file/shell tools: a set that names no `developer` builtin (None, or one that forgot it) leaves the agent unable to read files or run commands, and until now nothing reported it. `hasFileShellTools` (pure, tested) reads the extension list goose reports — the plan cannot answer it, because a newly created session with no extensions gets nothing while a resumed one keeps goose's implicit `developer`.
- 2026-11-23: the wizard preselects `Default` in a directory with no project history, instead of `None`: a fresh clone used to open an agent with no file or shell tools, because None means no extensions at all (`defaultSetSelection`, tested; an explicit None or Default in the history is kept as it is).
- 2026-11-23: version 3.7.0-rc.2 — carries the two fixes merged since rc.1 (release artifacts named after the host that compiled them; a session is never left silently without file/shell tools). `install-release.sh` now maps `arm64`/`aarch64` to `arm64`, the name `build.sh` actually produces, so the two agree.
- 2026-11-23: the "no file/shell tools" warning names `/set`, the remedy that keeps the conversation: it reconciles the extension list in place (verified live — a session created with no extensions gains `developer` and its tools). A project meta that recorded `""` under the old default keeps saying `None`, so relaunching alone does not repair it.
- 2026-11-23: the no-tools warning keeps a fallback: `/set` reconciles in place, but when an agent still reports no tools, a new session is the reliable path (both measured on goose 1.59.2 with custom_deepseek/deepseek-flash).
- 2026-11-23: `AGENTS.md` catches up with the code: the set step preselects `Default` in a directory with no history, extension warnings cover three cases (profile leak, missing expected extension, no `developer` at all) plus the `/set` remedy and its new-session fallback, and `build.sh` names the artifact after the host (`<os>-<arch>` from `uname`) with the glibc gate scoped to Linux.
- 2026-11-23: macOS is a published platform: `release.yml` gains a `build-darwin-arm64` job (macos-14) uploading `rossii-<ver>-darwin-arm64`, `update.ts`/`install-release.sh` accept it (Intel macOS and ARM Linux still refuse, by name), and `build.sh` writes the `.sha256` with `shasum` where `sha256sum` is absent. Both updaters now default to `artificemachine/goose-tui`: they pointed at upstream `viorn/rossii`, whose last release is v3.6.1, so updates on this fork could never see its own candidates.
- 2026-11-23: `monokai` stops being the odd theme out: its chrome now sits on the retrowave ladder instead of its own `#272822` tints, which put the agent (L\*16), tool (15) and shell (12) bands within four lightness points of each other and left the sections distinguishable only by hue — the agent band is a neutral `#404040` (no hue at all, L\*≈27), the tool band `#66D9EF` darkened to ≈16, the shell band black (≈3), the user band `#AE81FF` lightened to the retrowave mauve (≈72), the composer keeps `#272822`-adjacent `#181814`; `tests/theme.test.ts` measures every chrome theme's L\*, hue and contrast and fails when one leaves the ladder or its colour family (green or neutral / blue / mauve / black), and `scripts/theme-surface-test.ts` pins monokai's rendered surfaces.
- 2026-11-23: the status bar becomes the HUD of the reference (pi-bar's powerline footer): a row of slanted chips cut out of `\ue0ba`/`\ue0bc` instead of a full-width band, each chip's separators painted as foregrounds and every body closed with a full reset, so the bar itself paints **no background** and the terminal shows through (`retrowave`, `retrowave2` and `monokai` all lost their `statusBg`). The chip colours are the reference's own neutral greys (`STATUS_CHIPS`: `#303030`, `#555555`, `#626262`, `#414141`), identical in every theme — the third one a shade below the reference's `#707070` so a theme's near-white text clears AA on it (4.6:1, not 3.8:1); the chat feeds it segments (`StatusSegment[]` — model, set, usage) instead of one pre-joined dim string, and a narrow terminal drops the chips that no longer fit rather than overflowing.
- 2026-11-23: rossii reports its own lifecycle to herdr, the way `pi-agent`'s `herdr-selfreport` does for pi: `src/herdr.ts` gates on `HERDR_PANE_ID` + `HERDR_ENV=1`, builds `herdr pane report-agent` argv with a pure function, and fires the spawn without awaiting it, so a missing or hung `herdr` can never slow a turn. The chat reports `working` when a prompt is sent, `blocked` while a permission prompt waits for the user, `idle` when the turn ends, the agent dies or the chat shuts down — the pane's dot now follows the session. `tests/herdr.test.ts` covers the gate, the argv, the monotonic seq, the drop of a repeated state and the swallowed failures.
- 2026-11-23: retrowave swaps its two dark bands per the owner's call: answers sit on the black surface and shell output takes the green one, so the prose is the quiet part of the screen and the command output is the coloured part (tool calls keep the blue band, the user its mauve). The band invariants stop encoding an order: they now measure the *set* — three dark steps at least five L\* apart, one black, one blue and one green-or-neutral, the light user band far above them, the composer a dark surface of its own — so a theme may put black on the answers (retrowave) or a neutral grey (monokai) without re-ranking anything.
- 2026-11-23: `monokai` mirrors retrowave's slots after the band swap, instead of carrying a band of its own: answers on its warm black, tool calls on its darkened `#66D9EF`, shell output on its lime green (`#A6E22E` turned toward green at the same lightness), and the user's message on the `#AE81FF` mauve. A neutral grey answer band and the pink `#F92672` are both refused — the palette slot no longer decides which section gets which surface, so switching theme cannot re-rank the conversation; `tests/theme.test.ts` now pins each *slot* (black answers, blue tools, green shell, mauve user) instead of accepting any arrangement of the three dark bands, and `retrowave2` keeps the same slots as `retrowave`.
- 2026-11-23: the conversation loses its frame — no `╭╮╰╯` corners, no side `│` bars, in `monokai`, `retrowave` and `retrowave2` (and in the unthemed themes, which never had one worth keeping): `conversationView(document)` is now a bare `ScrollView` over the transcript. The section bands already close every block, the composer draws its own horizontal rules and the status strip closes the screen, so the box only cost two columns of width and two rows of height on each themed surface; `scripts/theme-surface-test.ts` now asserts the absence of the corners and the vertical bars instead of pinning them, and SPEC-002 gains REQ-019.
- 2026-11-23: the recap gets the surface it has in pi: goose answers `/recap` with an ordinary assistant message, which used to read as one more answer in the transcript. `src/acp/recap.ts` recognises the `※ recap:` marker (`isRecapText`, tolerant of the `\n\n` goose sends before it and of a chunk that stops inside the marker, but not of a lone `※`), bends it into `※ recap: <body> (disable recaps in /recap-config)` (newlines collapsed, an existing hint never doubled, words wrapped with one column of padding rather than truncated) and parses `/recap-config [on|off|toggle]`; `RecapSurface` renders it as the first row of the composer stack, above the editor, so it stays put while the conversation scrolls and the composer never jumps (a null line is one empty row). `handleSessionUpdate` routes a recap message to that line and opens no answer block, appending its later chunks and releasing only the streaming target at the end of the message, so a replayed history restores the line too; `/recap-config` saves the choice per directory (`recap: { enabled }`) and off leaves `/recap` working with its answer in the transcript. `tests/recap.test.ts` covers the marker's edge cases, the one-line shape, the wrap and the routing; the composer's height and the muted colour are pinned in `scripts/theme-surface-test.ts`.
- 2026-11-23: the recap line is on by default, and only an explicit `/recap-config off` turns it off: `readProjectRecap` answers `true` for a directory with no meta, no `recap` key, or an unreadable one, and `scripts/project-recap-test.ts` proves it in its own process (the projects directory is resolved at import time) — off and on again, the key surviving `writeProjectMeta`, and the two empty states.
- 2026-11-23: recaps become automatic, as in pi: `armAutoRecap` (`src/acp/recap-auto.ts`) is armed when a turn ends and cancelled by the next prompt, a steer, `/recap-config off|auto off` or shutdown; when it fires it sends `/recap` **quietly** — `submitPrompt` consumes `ctx.quietPrompt` to skip the `❯ /recap` echo and the dashed turn rule, so the only visible result is the line above the composer, and a replayed `/recap` message is not rendered either. The decision is pure (`shouldAutoRecap`): recaps on, automatic on, no running turn, no open permission, an empty composer, at least three turns, and at least one turn since the last recap (pi's `neverTwiceInARow`, measured as `turnsStarted` at the moment a recap is routed); an errored turn arms nothing. `/recap-config` gains `auto on|off|toggle` and `auto <delay>` (`30s`, `2m`, `off` = never, the `/timeout` grammar), and the project meta stores `recap: { enabled, auto, idleMs }` by merging — one facet never resets another — all defaulting to on/on/30 s. `tests/recap-auto.test.ts` proves arm, cancel and fire against a fake client on the real one-second floor; `tests/recap.test.ts` covers the grammar, the trigger's guards and `isRecapCommand`.
- 2026-11-23: two bugs the live probes found, both in the streaming decision. goose delivers `※ recap:` in pieces (`※`, ` recap`, `:`), so the old `isRecapText` — which refused a bare `※` — opened an answer block on the first chunk and the recap never reached the line; `classifyRecapHead` now returns `recap` / `answer` / `undecided` and the chat buffers while the head is still a prefix of the marker (a `※` that opens something else is flushed as an answer, `※ recapitulate` included). And because the line was never set, `lastRecapTurn` never moved, so the idle timer re-armed after its own recap and the session recapped itself in a loop — `submitQuietRecap` now records the turn when it *asks*, not when the answer arrives. `ROSSII_GOOSE_BIN` (and `bin:` in the ACP spawn) runs a goose that is not the one on PATH, which is how the probes are pointed at a build from source; `scripts/acp-recap-probe.ts` and `scripts/acp-recap-auto-probe.ts` prove the command and the automatic timer against a real agent.
- 2026-11-23: the recap line stops at **two rows**, whatever the model answers. A recap that came back as prose with bullets (`- **Thème Monokai** : …`) painted a six-row paragraph above the composer, which is not a glance and pushes the composer down; `RECAP_MAX_ROWS` = 2 is now the contract, enforced in `wrapRecapLine` (where the width is known, so the same recap is two rows at 120 columns and still two at 40). The body is flattened first — `**bold**` and backticks lose their syntax, bullets become `·` — and capped at `RECAP_BODY_MAX` (150 columns, cut at a word and marked `…`). When the cut happens the way out is kept: `elideAroundHint` reserves the columns of `(disable recaps in /recap-config)` and shortens the body around them, so a truncated recap still says how to turn itself off; only a width too narrow for both falls back to eliding without the hint. `tests/recap.test.ts` pins the cap at five widths, the ellipsis, the surviving hint and a too-narrow terminal; `scripts/theme-surface-test.ts` pins the rendered surface at 60 and 120 columns.
- 2026-11-23: a recap that quotes an earlier recap is flattened too. goose's answer summarises the conversation, and the conversation contains the previous `※ recap:` line — inside a fenced block, once the model quoted it back. `buildRecapLine` now drops code fences before the inline-code rule (a fence used to leave a literal ``` at the head of the line) and strips a nested `※ recap:` marker, repeatedly, so the body can never open on the marker the line already carries. `tests/recap.test.ts` pins both.
- 2026-11-23: `Ctrl+E` is the terminal's again. On a Mac keyboard `⌘→` sends `^E` (end-of-line), and the chat had bound that byte to the external editor: pressing `⌘→` in the composer opened `vi` instead of moving the cursor, which is how the owner found it. The listener no longer consumes `^E`; `/edit` keeps the feature (`/` then `edit`, or the `/…` menu), and the hint line says so. `scripts/acp-esc-key-test.ts` pins that the byte falls through untouched.
- 2026-11-23: two silent failures around `/recap` now speak up. When goose answers a `/recap` as an ordinary prompt instead of running the command (observed live: the model reading "/recap" and writing prose), the turn used to end with no line and no explanation — `recapAsPrompt` (set where the answer block is opened) makes `finishTurn` say so. And a prompt sent while a turn runs is now **queued** with a "⧼ queued for after this turn" line instead of being dropped by `submitPrompt`'s early return, which is how a `/compact` typed mid-turn vanished; a *quiet* recap is still dropped, since the next turn end arms another one. Tests: `tests/recap-auto.test.ts` (the prose answer is reported, a real recap ends quiet) and the new `tests/chat-io.test.ts`.
- 2026-11-23: the status line names the project first. A window opened in `~/.worktree/<branch>` or in a subdirectory reported only provider, model and usage, so "which repository is this?" needed the header; the first chip is now the project name, cut from the working directory by `projectNameFromCwd` (a worktree resolves to the repository it belongs to, not to the branch name) — pure string work, since the bar is rebuilt on every usage update. The no-colour fallback also stopped painting past the edge: it keeps the labels that fit and drops the rest. `tests/surfaces.test.ts` pins the order and the name resolution.
- 2026-11-23: the branch follows the project. With the repository named first, the second question is the one the repository cannot answer: which branch this window is on — and a session opened in `~/.worktree/<branch>` exists precisely to differ from the main checkout. `readGitBranch` (`src/worktree.ts`) reads `rev-parse --abbrev-ref HEAD`, answers `detached@<short-sha>` on a detached checkout (the literal `HEAD` is not a label), and null outside a repository or without git — the chip is then simply absent. It is read once when the chat is built and again at the start of each turn (`refreshBranch`, one `rev-parse` per prompt, never per frame), so a `git switch` in another window is picked up at the next prompt; `formatBranch` cuts a name longer than 32 columns **in the middle**, because both ends identify a branch (`feat/…-assets` reads, `feat/darwin-release-…` does not). `tests/surfaces.test.ts` pins the chip order (`project`, `branch`, `model`, `set`), its absence outside a repository and the elision.
- 2026-11-23: the status line's model chip names **only** the model. `custom_deepseek/deepseek-flash` spent fifteen of its columns on the provider half — a fact that does not change the answer and that the header still carries, next to the working directory. The chip now reads `deepseek-flash`, which leaves the width to the project and the branch that were just added; `tests/surfaces.test.ts` pins it.
