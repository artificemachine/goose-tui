# plan — единая клавиша перевода строки в composer'е (Ctrl+J vs Shift+Enter)

## Вопрос пользователя

В обычном терминале новую строку в composer'е rossii даёт `Ctrl+J`, а в терминале VS Code —
`Shift+Enter`. Почему так и как сделать единый UX?

## Ожидания до работы

1. Найти, где обрабатывается перевод строки: rossii (`src/acp/*`) или `@earendil-works/pi-tui`?
2. Объяснить разницу с точки зрения байтов, которые терминал кладёт в stdin
   (не «магия терминала», а конкретные последовательности).
3. Проверить поведение эмпирически: какие последовательности `Editor` реально считает новой
   строкой, в режиме без keyboard-протокола и с активным Kitty-протоколом.
4. Проверить, какие механизмы настройки уже есть в pi-tui (глобальные keybindings), т.е. можно ли
   сделать выбор клавиши конфигурируемым без форка библиотеки.
5. Выдать ранжированные варианты «единого UX» с ценой/риском и явно отметить непроверенное
   (что именно шлёт терминал VS Code — локально VS Code desktop не установлен, сеть недоступна).

## Вне скоупа

- Правки кода и README (сначала решение пользователя, какое поведение считать целевым).
- Проверка на живом VS Code / kitty / GNOME Terminal (нет доступа в этой сессии).
